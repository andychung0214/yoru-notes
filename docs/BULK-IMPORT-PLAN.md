# 整批歌詞匯入計畫

## 需求與範圍
一個 JSON 檔即可匯入目前所有歌曲（現在 16 首），數量從歌曲資料取得，不寫死。六欄為 ja、zh、en、hiragana、katakana、kanji；既有單首匯入與九種閱讀模式不變。延續純靜態、僅在本機儲存的設計。

整批格式為 `{ "version": 1, "songs": [{ "id": "yoru", "title": "夜に駆ける", "rows": [...] }] }`。ID 為配對依據，title 只供辨識。支援部分曲目更新，未列出或 rows 為空陣列的歌曲不動。下載範本由目前歌曲資料產生，含所有 ID、曲名與空 rows，以及 rowTemplate 六欄格式提示。

## 里程碑與工作分解
1. 核心：先以測試定義整批解析、動態曲目、未知／重複 ID、空資料、六欄及容量限制，再實作。
2. 介面：單首／整批模式、JSON 檔案或貼上、範本下載、待匯入與覆寫首數提示。檔案讀取或模式切換不允許舊內容誤送出。
3. 儲存：全部驗證後一次寫入；失敗時不更新記憶體與既有資料，保留對話框及輸入供修正。
4. 驗證：核心、瀏覽器、16 首逐首檢查六欄、重新整理、部分更新、錯誤不覆寫、容量拒絕、非同步檔案讀取、手機、鍵盤及下載格式。
5. 獨立程式碼審查、修正、文件與證據、提交；顯示 remote／branch／commit 後推送，確認 Pages 公開版本。

## 風險與驗收條件
- 保留每首 500 行、每欄 1000 字元、每首 rows 的 JSON 200 KB 限制；整檔限制依目前歌曲數量計算（每首預留 210 KB，外加 1 KB），可容納各曲及 metadata。localStorage 容量另受瀏覽器限制，儲存失敗時整批不生效。
- 未知 ID、重複 ID、無效 rows、檔案超限、版本不符須具體提示，且不改既有歌曲。空 rows 只略過，不刪除。
- 先保留原始 JSON；不自動翻譯、不產生歌詞，不會上傳匯入內容。
- 歌曲數增至 17 首時，解析與範本仍有效；測試用合成曲目驗證，不變更正式曲目資料。
- 預覽顯示待匯入、覆寫及略過首數，成功提示實際首數；所有內容仍以純文字呈現。
